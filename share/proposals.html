2

Mobile “Now” homepage

Replace the ticket inbox as the default landing screen with a mobile work cockpit.

Recommended: mobile-specific hierarchy using shared web data

Decision

Build a mobile-specific homepage that reuses the upcoming web homepage and dashboard data, permissions, and components. The mobile hierarchy should focus on the next action rather than reproducing the web layout.

What appears first

  • The three items that need attention now, with the reason each matters.
  • Universal Ask Onflo search across tickets, people, assets, locations, and knowledge.
  • Quick actions for a new ticket, asset scan, and Ask Flo.
  • Role and Module context, with IT, Facilities, and supervisor variants later.
Home answers: What needs me now?
Dashboard answers: How is the operation performing?

Data strategy

Reuse web dashboard APIs and definitions. Compose them into a faster mobile view with local cache, progressive loading, and direct actions.

One-screen ticket creation

Replace the multi-page wizard and accordion stack with one progressive, context-aware form.

Proposed: one scroll, no required student or staff gate

Flow

Choose General, Global, or IT at the top. Search for a person immediately. Student and staff remain optional filters, not a required first step.

Information order

  • Show completed context first: person, role, topic, and known device.
  • Then show only the missing fields required for this ticket type.
  • Filter linked assets to the selected customer.
  • Keep voice input and AI cleanup beside every long-text field.
  • Preserve the form if the user is interrupted or loses connectivity.
Key rule: Do not make users re-enter information the app already knows.

What changes from the prototype

General, Global, and IT share one form shell. Ticket type changes the relevant fields instead of sending the user through separate page stacks.

4

Mobile dashboards

Keep the web's trusted metrics and drill-downs, then rebuild their hierarchy for a phone.

Recommended: shared data, mobile composition

Relationship to the homepage

The homepage is personalized and action-first. Dashboards are deliberate reporting views for team health, trends, comparison, and drill-down.

Keep from the web

  • Service Overview definitions, filters, periods, and permissions.
  • Metrics that open the exact filtered ticket list behind the number.
  • AI summary, trending themes, team load, and SLA risk.

Change for mobile

  • One reading column with the strongest number first.
  • Two-up metric cards, compact charts, and ranked lists.
  • No desktop grid editor, CSV download, or dense word clouds.
  • Share stays because mobile is a good place to send a report.
Recommended first board: Service Overview, because it supports the homepage and demonstrates immediate operational value.

Acceptance checklist

Small, testable requirements.

Draft requirements, dates not assigned

Performance

Useful content appears within 0.5 seconds.
Local state or a useful transition appears while fresh data loads.
Drafts, scroll position, and captured media survive interruption.

Homepage

The app does not default to the ticket inbox.
The first view explains what needs attention and why.
Role and Module context shape the experience.

Ticket creation

Student or staff is an optional filter.
Completed fields appear before missing fields.
Only relevant fields and customer assets appear.

AI and input

Long-text fields support voice and transcription.
Users can ask AI to clean up drafted text.
Photos can identify and link device information.
AI suggestions are visibly different from confirmed data.

Accessibility

Important targets aim for 44 by 44 pixels.
Dynamic text and screen readers preserve meaning.
No important action depends only on a gesture.

Review evidence

Visual timeline tells the release story.
Homepage demonstrates the new mobile philosophy.
Ticket flow demonstrates fewer pages and taps.
Dashboard demonstrates shared data in a mobile hierarchy.

Future, unscheduled  Offline-first synchronization remains tracked as a later engineering effort and is not part of the current release promise.
